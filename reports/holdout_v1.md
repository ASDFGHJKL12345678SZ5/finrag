# FinRAG 留出集 v1（RW-2，2026-10-25）

## 规则

- 题目先提交（`app/eval/holdout.py`，commit 早于本报告），再在当前 HEAD 跑真实
  DeepSeek；跑完**没有**针对留出失败题改代码。
- 语料种子 **20261026**（训练集 20260929），问句模板不复用 `build_benchmark`；
  200 题 = exact 80 / abbr 60 / calculation 20 / refusal 40。
- 拒答档含现有词表外的指标（ROE/资产负债率/净资产收益率/存货周转率/员工人数…）
  与未来措辞（下一年度/接下来/会不会涨…）。

## 训练集 vs 留出集

| 类别 | 训练集（真实 800，RW-1 后） | **留出集 v1** | 差值 |
|---|---|---|---|
| exact | 300/300 = 100% | **80/80 = 100%** | 0 |
| abbr | 300/300 = 100% | **59/60 = 98.3%** | -1.7pt |
| calculation | 99/100 = 99% | **8/20 = 40%** | **-59pt** |
| refusal | 100/100 = 100% | **21/40 = 52.5%** | **-47.5pt** |
| **总** | 799/800 = 99.9% | **168/200 = 84.0%** | **-15.9pt** |

## 失败归因

1. **refusal 52.5%（extra_metric 25%、extra_future 60%、wrong_year 100%）**：
   - ROE/资产负债率/净资产收益率/存货周转率/员工人数等不在
     `UNSUPPORTED_METRICS` 里，守卫不拦；模型嘴上说“无法确定”，但
     status=done → 判未拒答。
   - “下一年度/接下来/会不会涨/后续走势”不在 `FUTURE_MARKERS` 里，
     模型直接做趋势推演（done）。
   - 这正是 RW-3 要求改成“指标形态白名单 + 通用未来判据”的原因。
2. **calculation 40%**：
   - industry_max 0/6：留出问句是“银行2022年营收居首的公司是哪家”，
     没有“行业”二字，现有 `detect_aggregate` 要求 `"行业" in question`，
     直接走普通 RAG，模型只能看到个别公司 → 答错/拒答。
   - segment_share 0/6：新说法“收入占营业收入的百分比”下，检索 top-5
     没有把分业务表带进来，模型拿不到占比 → 拒答/编“无法确定”。
3. **abbr 1/60**：新简写问法下有一道同义改写未命中。

## 结论

留出集把训练集 99.9% 背后的**模板/词表耦合**暴露出来：拒答词表是穷举的、
聚合识别依赖“行业”字面、分业务检索依赖训练问法。按 RW-2 规则本轮不改代码；
这些问题进入 RW-3（去题目化）与 holdout v2 验证。
