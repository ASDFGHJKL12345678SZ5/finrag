# FR-4 1000 篇真实语料对照（eval DB，8000 块）

语料：FR-1 难基准 200 公司 × 5 年 = 1000 篇 / **8000 块**（`finrag_eval`）。
查询：从 800 题基准取前 40 条（覆盖精确/简称/计算），top-5。
旧实现 = `_keyword_search_legacy`（12 路 ILIKE 全表 + 表达式排序）；
新实现 = `keyword_search`（倒排 posting + BM25 + 预计算 df）。

| 指标 | 旧（ILIKE + 全表 df） | 新（倒排 + 预计算 df） | 加速 |
|---|---|---|---|
| 关键词检索 P50 | 183.3 ms | **47.1 ms** | **3.9×** |
| 关键词检索 P95 | 188.2 ms | **58.1 ms** | **3.2×** |
| df 计算 P50 | 184.2 ms | **1.48 ms** | **124×** |
| df 计算 P95 | 187.3 ms | **1.80 ms** | **104×** |

比 8,000 块合成基准（P50 133.7 → 111.5ms）提升更明显：真实研报块更长、
二元组更多，旧路 12 路 ILIKE 的逐行字符串成本随文本长度上升；倒排只按
posting 数量增长。**这是 1000 篇规模上的最终对照数字。**

诚实边界：EXPLAIN 显示 BM25 仍需把命中 chunk_id join 回 chunks（8k 行 ~1ms），
不是"完全无全表扫描"；但 12 路 ILIKE 与全表 df 都已消失，收益主要来自
df 预计算（124×）和避免逐行字符串匹配（3.2–3.9×）。
