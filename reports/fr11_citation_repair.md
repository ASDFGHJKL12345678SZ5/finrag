# FR-11 引用自动修复：算对了但引错块，不再被误杀

## 问题

真实 800 题里 `segment_share` 只有 **14/20**：模型算对了"占比 23.45%"，却引用
了多年营收表 `c2`（只有总营收），而含"占比 23.45%"的分业务表 `c1` 就在
retrieved 里。`verify` 按"被引块"逐数字核对，于是正确答案被判无据 →
`insufficient`。这是**引用选择错误**，不是算术/检索错误。

## 改法（`verify.repair_citations`）

逐句做确定性修复，不碰数字、不改文字：

1. 用现有 `split_claims` 拆出（论断，引用）；
2. 论断在已引块证据里不通过时，在**其余 retrieved 块**里找一块能通过
   `_missing_evidence` 的；
3. 找到就把该块引用号补到句首（`[cN]`），再交给原 `verify_answer` 重新判；
4. 找不到就原样返回——**绝不为了过校验放宽判据**。

图里的 `verify` 节点先 repair 再 verify；trace 记 `citation_repaired`，
答案文本更新为修复后的版本。

## 效果

- 单测：`test_verify.py` 新增 2 条——错块修复后 passed；数字真的不存在时
  unchanged 且仍不通过。
- mock 800：segment_share 19/20 → 19/20（mock 本来引用就准，修复不改变）；
- 真实 800：14/20 → **19/20**（另 5 道守卫误拒由词典补"收入"修掉，
  是 FR-11 同批改动的另一半）；唯一剩余失败是"因此……"结论句被内容词
  门禁判无据，数字本身正确。

## 边界

- 只补引用，不重新生成答案；如果答案里的数字在任何 retrieved 块都不存在，
  仍按原判据拒答（这是特性，不是缺陷）。
- 修复粒度是"句子"；一句多论断且引用不同块的极端情况不保证。

## RW-5 返工：修复必须先过“同公司 + 同指标”约束（2026-10-25）

**原问题**：旧 `repair_citations` 只要求“数字在另一个 retrieved 块里出现”，
数字碰巧相同、但公司不同的块也可能被拿来补引用，然后 `verify_answer` 用同一块
自证——修复可能把错误引用“洗白”。

**改法**：
- 候选块必须满足：`source` 解析出的公司简称在答案提到的公司集合里，且块文本
  含论断里的指标词（`METRIC_GROUPS` 说法）；找不到就原样返回。
- verify trace 记录 `pre_ratio`（修复前支持率）、`citation_repaired`、
  `repair_entities`；eval runner 汇总 `citation_faithfulness_before` 与
  `citation_repair_rate`。
- 新单测：数字相同但公司不同的块不得用于修复，且原答案仍判不通过。

**真实 800（RW-5 后）**：

| 指标 | 值 |
|---|---|
| 总分 | **797/800 = 99.6%**（exact 300/300、abbr 298/300、calc 99/100、refusal 100/100） |
| 修复前忠实度 | 99.64% |
| 修复后忠实度 | 99.62% |
| 修复率 | 16.6%（116/700 可答） |
| 修复后校验通过 | 116 例全部 status=done；20 例逐例抽查见 `rw5_spotcheck.md` |

边界：修复率是“答案里至少有一句被补引用”的比例；修复前后忠实度几乎持平，
说明修复主要补的是**引用指向**而不是改变答案正确性；abbr 2 道错因是数值/口径，
不是引用。
